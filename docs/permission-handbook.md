# Data-Khaos 权限手册（规划稿 v1）

> 目的：约束后续开发，明确 Data-Khaos 的组织架构与权限模型。本文档为**规划稿**，标识为「待定」的条目需在评审后调整。
>
> 核心诉求：当前系统无组织架构。引入 **组织(业务线) → 项目组 → 人** 三级模型，实现「加入系统即加入项目组，人加入项目组即获得组内权限与能力」。

---

## 1. 权限模型总览

```
组织 / 业务线（进系统先选）
├── 项目组 A ──┬─ 成员（人）
│              └─ 资源：开发任务 / 报表 / 表权限
├── 项目组 B ──┬─ 成员（人）
│              └─ 资源：开发任务 / 报表 / 表权限
└── 直属人（未入组，可后续加入项目组）
```

**授权链路**：

```
人（选组织进入）
  └─ 加入项目组（可多组，需切换当前组）
       └─ 获得项目组角色
            ├─ 能力位 capability_flags（操作权限：能做什么）
            └─ 资源集（数据权限：能看什么 — 表/行/列/报表/任务）
```

**两类权限**：
| 类型 | 决定什么 | 载体 |
|---|---|---|
| 操作权限（能力位） | 能不能做某操作（模型开发/浏览…） | 项目组角色 `capability_flags` |
| 数据权限（资源） | 能看哪些数据 | 表权限 + 行/列策略 + 组下资源 |

---

## 2. 核心概念与术语

| 概念 | 说明 |
|---|---|
| 组织 / 业务线 | 顶层租户/事业部，进系统必须先选择 |
| 项目组 | 组织下的业务协作单元，含成员、角色、资源 |
| 人（用户） | 归属组织，可加入多个项目组，需切换「当前项目组」 |
| 项目组角色 | 一组能力位的集合，`全局模板 + 组内自定义` |
| 能力位 | 可勾选的操作权限标识，如 `model:develop` |
| 资源 | 项目组绑定的开发任务 / 报表 / 表权限 |
| 当前项目组上下文 | 用户当前工作视角所属的项目组，判定权限以此为准 |

## 3. 组织架构

### 3.1 组织（业务线）
- 复用 `sys_organization`，语义收窄为「业务线/组织」，`org_type` 增加 `BUSINESS_LINE`。
- 组织是进系统的第一层选择。

### 3.2 项目组
- 归属于组织，一个组织可有多个项目组。
- 项目组下挂：开发任务、报表、表权限。

### 3.3 人
- 归属组织（`sys_user_org`）。
- **可加入多个项目组，需切换当前项目组**（`is_primary` 标记主组，亦可按用户切换）。

### 3.4 归属关系表
| 关系 | 表 |
|---|---|
| 人 → 组织 | `sys_user_org` |
| 项目组 → 组织 | `sg_project_group.org_id` |
| 人 → 项目组 | `sg_project_group_member` |
| 人 → 项目组角色 | `sg_project_group_member.project_role_id` |

## 4. 项目组角色与能力位

### 4.1 角色定义方式
- **全局模板**：内置 `组长 / 开发者 / 使用者` 三档。
- **组内自定义**：每个项目组可基于模板创建角色，并勾选能力位。

### 4.2 能力位清单（可勾选）

| 能力域 | 能力位 | 说明 | 默认组长 | 默认开发者 | 默认使用者 |
|---|---|---|---|---|---|
| 数据资产 | `meta:browse` | 元数据/血缘/表结构浏览 | ✔ | ✔ | ✔ |
| | `query:execute` | 临时库查询 | ✔ | ✔ | ✘ |
| | `table:manage` | 建表/改表（表管理） | ✔ | ✘ | ✘ |
| 模型 | `model:develop` | 语义模型开发 | ✔ | ✔ | ✘ |
| | `model:publish` | 模型发布/上线 | ✔ | ✘ | ✘ |
| | `model:browse` | 模型只读浏览 | ✔ | ✔ | ✔ |
| 报表 | `report:develop` | 看板开发/编辑 | ✔ | ✔ | ✘ |
| | `report:publish` | 看板发布/上线 | ✔ | ✘ | ✘ |
| | `report:browse` | 看板只读预览 | ✔ | ✔ | ✔ |
| 任务 | `task:develop` | 调度任务开发 | ✔ | ✔ | ✘ |
| | `task:schedule` | 任务启停/调度 | ✔ | ✘ | ✘ |
| 审批 | `approval:apply` | 发起权限申请 | ✔ | ✔ | ✔ |
| | `approval:approve` | 审批他人申请 | ✔ | ✘ | ✘ |
| 管理 | `pg:manage` | 项目组成员/角色/资源管理 | ✔ | ✘ | ✘ |

> 能力位为**标识符清单**，可按需增删；前端据此显隐菜单与按钮。

## 5. 表权限（两种主体并存）

**决策**：表权限既可由**个人**拥有，也可由**项目组（用户组）**拥有，两种并存，取并集。

### 5.1 授权主体
| 主体 | 字段 | 说明 |
|---|---|---|
| 个人 | `user_id` | 精确授予某用户某表的权限 |
| 项目组 | `project_group_id` | 授予整个项目组，成员自动获得 |

### 5.2 授权粒度
- 表级：`datasource_id + database_name + table_name`
- 操作类型：`SELECT / INSERT / UPDATE / DELETE / ALL`

### 5.3 生效规则
- 个人与项目组取**并集**（拥有任一即放行）。
- 个人授权优先级高于项目组（用于收敛个别成员的越权）。
- 数据行/列级继续由行/列策略约束（见 §6）。

---

## 6. 行 / 列级安全策略

- 沿用 `sys_row_policy` / `sys_column_policy`。
- 支持绑定：个人 / 角色 / **项目组**。
- 行策略表达式支持 `#{currentUserId}` / `#{currentOrgId}` / `#{currentProjectGroupId}`。
- 列策略支持 `MASK / ENCRYPT / HIDE / PLAIN` 脱敏。

## 7. 各业务模块权限要求（按模块）

以下为「能做什么」+「能看什么」的逐模块需求，是开发约束的入口。

### 7.1 数据资产（元数据 / 血缘 / 表结构）
| 项 | 要求 |
|---|---|
| 能力位 | `meta:browse` |
| 能看什么 | 仅当前项目组已授权数据源下的表结构、血缘、字段 |
| 约束 | 表列表/结构/血缘接口按「当前项目组上下文」过滤 |

### 7.2 数据查询（QueryWorkbench）
| 项 | 要求 |
|---|---|
| 能力位 | `query:execute` |
| 能看什么 | 仅当前项目组已授权表；受行/列策略约束 |
| 约束 | SQL 执行前做表权限校验 + 行/列策略注入；导出 CSV 需 `query:execute` |

### 7.3 语义模型（Mart）
| 项 | 要求 |
|---|---|
| 能力位 | 开发 `model:develop` / 发布 `model:publish` / 浏览 `model:browse` |
| 能看什么 | 仅当前项目组可见的模型 |
| 约束 | 模型列表按项目组过滤；发布操作需 `model:publish` |

### 7.4 报表（Visual）
| 项 | 要求 |
|---|---|
| 能力位 | 开发 `report:develop` / 发布 `report:publish` / 浏览 `report:browse` |
| 能看什么 | 仅当前项目组可见的看板；数据受表权限+行/列策略约束 |
| 约束 | 预览模式 `?preview=1` 对应 `report:browse`；分享链接只读 |

### 7.5 任务调度（Schedule）
| 项 | 要求 |
|---|---|
| 能力位 | 开发 `task:develop` / 调度 `task:schedule` / 浏览 |
| 能看什么 | 仅当前项目组创建的任务与日志 |
| 约束 | 他人任务不可见；启停需 `task:schedule` |

### 7.6 权限申请 / 审批（Approval）
| 项 | 要求 |
|---|---|
| 能力位 | 发起 `approval:apply` / 审批 `approval:approve` |
| 约束 | 申请类型含 表/报表/数据源；审批流按项目组负责人/模板 |

### 7.7 管理
| 项 | 要求 |
|---|---|
| 项目组管理 `pg:manage` | 成员增删、角色配置、资源绑定 |
| 组织管理 | 组织管理员管理本组织下项目组与人 |
| 平台管理 | 超级管理员（`SUPER_ADMIN`）全量权限 |

## 8. 权限判定流程

```
登录 → 选择组织(业务线) → 进入组织空间
  → 加载组织下：项目组列表 + 直属人
  → 用户选择/切换到「当前项目组」
  → 取当前项目组角色能力位(操作权限)
  → 汇总当前项目组的资源：表权限(个人+项目组并集) + 报表/任务
  → 菜单/路由/按钮按能力位过滤
  → 数据查询按表权限 + 行/列策略过滤
```

**优先级（由低到高）**：
1. 全局兜底/组织继承
2. 项目组角色能力位
3. 个人表权限（最精确）

## 9. 表结构规划

### 9.1 新增表
| 表 | 关键字段 | 说明 |
|---|---|---|
| `sg_project_group` | `id, org_id, project_name, project_code, leader_id, status` | 项目组 |
| `sg_project_group_member` | `id, project_group_id, user_id, project_role_id, is_primary` | 成员 + 组内角色 + 主组标记 |
| `sg_project_role` | `id, org_id, project_group_id, role_name, capability_flags(JSON), status` | 组角色；`project_group_id` 空=全局模板 |
| `sg_project_group_resource` | `id, project_group_id, resource_type(TASK/REPORT/TABLE), resource_id` | 组下资源归属 |

### 9.2 改造表
| 表 | 改动 |
|---|---|
| `sys_organization` | `org_type` 增加 `BUSINESS_LINE`，语义收窄为业务线 |
| `sys_user_org` | 保留（人→组织） |
| `sys_table_permission` | 增加 `project_group_id` 维度（支持按组授权） |
| `sys_row_policy` / `sys_column_policy` | 增加 `project_group_id` 维度 |
| `sys_role` / `sys_user_role` | 过渡期保留，业务权限逐步迁移到项目组角色 |

## 10. 前端交互与约束

1. **登录** → 若多组织进入「选择业务线」页；单组织自动进入。
2. **组织空间** → 左侧「组织下项目组 + 人」导航，进入项目组空间。
3. **当前项目组切换** → 顶部全局切换器，切换后整体权限视角刷新。
4. **能力位过滤** → 复用 `UserPermissionDto.permissions`：菜单、路由、按钮按能力位显隐。
5. **数据权限** → 查询/看板数据按「当前项目组」的表权限 + 行/列策略过滤。

## 11. 已确认决策

| 决策 | 结论 |
|---|---|
| 多项目组归属 | 可加多组，**需切换当前项目组** |
| 角色定义 | **全局模板 + 组内自定义** |
| 表权限主体 | **个人 + 项目组 两种并存，取并集** |
